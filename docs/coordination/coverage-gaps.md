# UI、前端与测试规划覆盖核对

2026-11-13，依据用户问题及当前台账实查。本文是缺口登记及补齐方向，不是完整实施计划、视觉设计批准或任务派发。

| 工作线 | 目前确有的内容 | 缺少的可执行规划 |
| --- | --- | --- |
| UI/UX | 终端、角色、业务规则与接口设计 | 各角色旅程、导航与页面清单；关键原型与视觉规范；空/错误/到期/未授权等状态；审阅与验收 |
| Web前端 | 需求明确商家/平台及用户入口、教练和客服独立入口 | 按角色和业务闭环拆任务；组件单一归属；技术方案；模拟接口及真实联调任务 |
| 微信小程序 | 用户端范围及跨端一致性要求 | 页面与交互、平台能力边界、前端工程选择；按记录/会员/预约/榜单等独立交付拆分；开发工具与真机验收区分 |
| 后端测试 | 003A上下文/安全边界测试；005V金额数据已验收 | 各业务权限、状态、接口、持久化、失败/并发与迁移验证，随模块实施 |
| 前端测试 | 尚无独立前端任务 | 组件与交互、表单校验、错误状态、角色入口、多尺寸/基础可访问性、小程序环境验证 |
| 真实联调/E2E | TASK-009容器及路线图出口 | 按业务闭环的逐阶段联调；跨端同账号；多商家/门店隔离；支付退款/权益/课程的正常及异常验证 |
| 上线质量 | L06/L08及隐私等上线门槛 | 环境、真实开放渠道、备份恢复、监控、必要负载/安全及上线检查的独立任务和证据 |

补齐顺序建议：先形成各角色旅程与页面/验收清单，同时形成分层测试策略；再审关键原型、明确前端技术和公共组件边界；按获批契约并行开发对应Web/小程序流程与后端流程；每个闭环各自真实联调，最后跨模块上线验收。

不能要求UI信息架构等全部等待后端完成；也不能以可点击原型或模拟数据页面代替业务交付。未定价格等只阻塞相关展示/交易规则，不应阻塞无关页面结构。当前没有新UI/前端执行聊天或Prompt，本记录不声称已经补齐完整计划。
