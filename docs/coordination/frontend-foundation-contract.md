# PAR-003客户端契约 v1（COORD-01维护）

依据DEC-020账号开发接口、DEC-021用户批准结构/技术及UX PAGE-01/02/03。这是有限前端实现输入，不发布新的健康业务API，也不替代服务端权限。

## 范围与模式

每端完整实现登录、首页/会话上下文、三类手动记录新增及本人列表、退出和刷新失败。体重仅数值kg、饮食仅食物名/分量文本、训练仅名称/分钟数；各例含本地id、kind、occurredAt与输入字段。记录DTO为客户端模拟数据格式，不是最终C09；趋势图、热量/营养估算、AI、付费榜、会员交易、健康授权/注销不在本批。

AppMode=mock或live-auth。默认mock显著显示“演示数据，未连接真实业务，请勿输入真实健康资料或密码”；记录均只在内存按模拟主体隔离，刷新页面/冷启动清除，不用浏览器localStorage/wxStorage持久化健康或Token。local token仅内存；冷启动重新登录属于当前开发设计，不宣称持续登录体验完成。

mock认证只用于界面和测试，不能发请求给真实服务或伪造服务端授予。live-auth仅调用003B四接口；记录区仍显著标“记录演示，未保存到服务器”，不发尚未实现的C09请求。真实认证失败/超时/503绝不自动转mock成功；模式转换清Token/草稿/主体缓存，不把模拟Token发送给live服务。

## 认证适配锁定

首次登录响应必须含generation=0，首次刷新用0，刷新成功取返回的新generation；不解析opaque Token猜代数。此为协调者补齐跨端契约，需003B原执行者读取最新计划，不宣称已自动送达。

按plans/TASK-003B.md实现POST /v1/sessions、POST /v1/sessions/refresh、DELETE /v1/sessions/{id}、GET /v1/me/contexts，JSON/Idempotency-Key/错误信封及authnSource=LOCAL_DEV保持；不得自创用户名密码顶层字段或注册接口。发送entry=user-web/user-mini及平台clientKind，不在请求传role/accountId授予身份。

同一并发失效只触发一次刷新并共用结果，刷新失败/409 REAUTH_REQUIRED时清会话回登录，重试最多一次，禁止无限刷新环。退出即清客户端状态；退出API失败保留失败说明，不宣称服务端已吊销。切主体清记录和草稿；staffScopes/entitlementSources为空时不显示虚构商家权限或付费能力。只展示服务端明确提供的可用入口，切身份或店不是增加权限。

Web仅使用开发代理接loopback后端，不为省事改服务端CORS；mini在开发工具允许本地测试的条件下配置地址，不伪造AppID、服务器域名或真实微信认证。003B尚未验收/环境不可用时交付mock代码和live适配测试，但真实联调必须标待验收。

## UI与验证

遵循UX信息结构，Web多尺寸、小程序触控布局分别实现，不把1200宽桌面图等比例缩小当手机设计。灰阶线框中的P编号、hold、UNKNOWN、mode等评审技术字不作为产品主文案；界面用“退款处理中/服务暂不可用”等业务语义，模拟标识仍保留。当前无退款页面，不为了展示文案扩范围。

用户手动输入需字段内错误、时间/单位清楚、重复提交保护、保存/返回、列表空态、失败重试、不丢非敏感草稿；正数/有限数与合理长度校验由实现者明确并测试，示例范围不能冒充医疗标准。保留键盘可达/标签/焦点/对比度及小屏可用性。

跨端共享约定仅此文档，运行代码各自目录独占；不要建立root workspace/shared包或互改锁文件。QA引用005/019/029及当前DEC开发子集，原G1中的关闭等不是本批验收前置。真实健康持久化、完整跨端认证和小程序真机另验收，不将模拟算完成。
