# PAR-003 Web与小程序基础闭环实施计划

> 执行方式：两个独立用户工作聊天，各用executing-plans完成自己整个闭环，不按文件或组件拆成新任务。协调者不开发业务代码。

**Goal:** 两端分别交付可运行的登录/首页/手动记录交互、认证适配和必要测试。
**Architecture:** web和mini互不共享可写包，backend由003B唯一维护；mock/live-auth分离，记录模拟明确，后续独立真实联调。
**Tech Stack:** 用户批准Web Vue3+TS+Vite，mini原生TS；各执行者先官方核实Node/TS/框架及测试工具兼容，选稳定明确版本写package.json和独立lockfile，不盲升latest跨主版本，不改系统Node。当前registry latest TS可能跨主版本，不能假定vue-tsc或开发工具支持。
**Spec:** frontend-foundation-contract.md v1、UX906fc7a、QA5df227b、DEC-020/021、TASK-003B四路由契约。

## 独占文件与接口

WEB001：web/package.json及lock、vite.config.ts、tsconfig文件、index.html、src/{main.ts,App.vue,styles,auth,adapters,features/home,features/records}/、测试及README，docs/deliveries/TASK-WEB001/**。MINI001：mini/package.json及lock、tsconfig、app.ts/json/wxss、pages/{login,home,records}/、services/{auth,adapters}/、测试及README，自己的交付目录。可按平台常规细化文件但不扩角色/功能。各自.gitignore放各自目录，不改root .gitignore、根lock或backend。

共同接口/模式/字段由frontend-foundation-contract.md锁定；运行时client helper为各端私有实现，HTTP适配器和mock适配器隔离。不依赖另一个前端任务或003B尚未完成的代码读取，契约变化回协调者。

## Task WEB001：一个完整Web交付

- [ ] 核对独立工作区及起点，读图/页面、共同契约与账号计划；官方核实兼容后锁定版本/依赖并记录来源，不安装系统软件。
- [ ] 在web初始化Vue3/TS/Vite并配置各端私有忽略项；完成mock与live-auth认证/记录适配接口、内存主体/会话边界。
- [ ] 先写失败测试：登录成功/无效证明、并发401只刷新一次、刷新失败回登录、退出清缓存且失败不假称吊销、模式切换不泄漏模拟Token；再实现。
- [ ] 实现登录、首页和上下文、三类记录新增/列表闭环，表单校验/空/加载/错误状态，响应式桌面/手机布局，不显示虚构员工权限；记录mock标识逐区域明确。
- [ ] 测试三类记录有效/非法/重复提交、换主体记录隔离、刷新清除、live错误无mock降级，截取至少登录/首页/记录和小屏截图并实际打开检查。
- [ ] 独立web目录运行npm ci、类型检查、测试和生产构建；用真实浏览器跑mock登录到新增/退出流程。若003B已验收且服务可用，另给live-auth探测证据；否则如实留待联调，不伪造。
- [ ] 记录实际命令/结果、未实现边界、接口差异，git diff --check及敏感/范围扫描后整体commit/push并交report.md。

## Task MINI001：一个完整原生小程序交付

- [ ] 同样核对独立起点和官方TS/基础库/工具兼容，初始化mini原生工程而非H5壳或跨端框架；版本与lock独立。
- [ ] 先写可执行的适配/状态单元测试，覆盖与Web相同的认证并发及隔离不变量；wx请求/内存接口可用受控测试替身，但不能冒充小程序实际运行证据。
- [ ] 实现login/home/records的WXML/WXSS/TS、导航、触控表单与状态，记录及Token仅内存；mock/live-auth边界同契约。
- [ ] 做编译/类型/单元测试；有开发工具就实际导入和操作、截图检查，不猜AppID或为演示声称真实微信认证。无法启动工具/游客测试能力时报告环境受阻和未验收部分，不能只凭tsc通过称小程序已可用。
- [ ] 报告开发工具/基础库/系统实际版本及本地请求条件；真机/授权账号/合法域名未就绪则单列，不提前索取当前不需要的配置。后续真机联调独立验收。
- [ ] 核对差异及敏感信息，任务整体commit/push并交报告，不为满足数量而拆成组件任务。

## 重点审查

1. live失败绝不模拟成功；2. Token/健康资料不入日志或持久缓存；3. 单飞刷新不无限重试；4. 空角色不自造权限；5. 记录模拟和真实认证状态分别展示。

每项有对应自动或实际交互验证；不能以截图代替测试，也不能以测试替身代替浏览器/开发工具。任务可并行交付和验收；缺真实后端/小程序环境仅阻塞相应验收阶段，不阻塞另一端代码。
