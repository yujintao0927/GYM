# TASK-005V 金额夹具与人工预期

状态：待验收。全部数值均为测试夹具，不是实际套餐价格、订单限额或真实交易。
输入：[需求退款章节](../../requirements.md)、[REQ索引](../../coordination/requirements-trace.md)、[TASK-002场景](../TASK-002/scenarios.md)、[契约](../TASK-002/contracts.md)、[待批政策](../TASK-002/open-decisions.md)、[状态设计](../TASK-002/states.md)。固定版本见[报告](report.md)。

## 数据约定与手工推导

[vectors.json](vectors.json) 根字段 schemaVersion 为字符串 `1`，cases 为数组；每例严格使用用户指定的八个字段。金额均为“分”的非负十进制整数字符串，单位为预先归一后的非负整数串，总量必须正且剩余不大于总量。不包含币种、商品状态或日期；不可从 TIME_RATIO 推断日历换算、补偿或激活规则。TIME_RATIO 对应 REQ-033，COUNT_RATIO 对应 REQ-034，均关联 REQ-032/035。

以下预期由数学分数手工确定，未调用 Java 或生产退款函数。计算一次比例后四舍五入到分，中途不舍入、无手续费、不追回折扣。小数表述只用于说明；校验器通过整数 divmod 独立核对，余数的两倍大于等于分母时进一。

| --- | --- | --- | --- |
| V01 | TIME_RATIO | 0×7/12=0 | 0 |
| V02 | COUNT_RATIO | 10000×0/12=0 | 0 |

## 需求与独立账务场景

REQ-036：健身房会员与私教订单分别申请、审核和记账；两者按商品快照选择 TIME_RATIO 或 COUNT_RATIO。V03/V16展示共用算术，不验证实际分账或商品类型选择。REQ-039/094：这里只接收已确定的申请快照数值，不验证申请时点取值、暂停及关闭权益。

以下仅定义后续账务验证输入及不变量，不是本脚本通过的测试：

| 场景与来源 | 后续输入/动作 | 期望不变量与未验证边界 |
| --- | --- | --- |
| 累计上限，REQ-035，D08 | 已存在退款流水，再尝试另一个退款或重放 | 累计实退不得超过实付。历史已退加本次比例金额可能超限时，具体处理留给账务契约；本夹具不擅自截断或拒绝，不将独立比例结果当新增可支付额度 |
| 申请和消费并发，REQ-039/094，D09 | 两个申请与一次消费竞争 | 同订单至多一个处理中申请；申请快照与hold一致，成功只关闭对应权益，其他卡独立。需事务/并发测试，重复计算不是证明 |
| 重复回调与重试，D08/D26 | 原指令重试、丢响应、迟到成功及重复通知 | 同一资金指令最多一次实退，不将UNKNOWN当失败另发指令；金额保持原快照。具体hold及人工政策仍按待批P07处理，未验证原子性、幂等、发送栅栏或渠道能力 |
| 币种及分账，REQ-036，C06/C07 | 相同数额但不同currency/mode/受益方或订单 | 资金事实须匹配原订单币种、受益方和模拟/真实模式，不能混币累计。这里“分”是固定测试尺度，不定义多币种精度/汇率；无currency字段不表示可用于任意币种 |

## 重放与损坏副本

从任意目录执行脚本均基于自身文件位置读取输入。仓库根命令：`python docs/deliveries/TASK-005V/verify_vectors.py`。独立反向命令：`python docs/deliveries/TASK-005V/verify_vectors.py --negative-only`。

四种内存深拷贝分别篡改V01期望、复制ID、把分母改零、把剩余改为13超过12。每例必须触发验证错误；如任一被接受，进程退出1。四例均被拒绝时测试驱动退出0，输出具体拒绝原因；这不表示损坏输入有效。正式fixture不被写入，脚本不生成缓存或临时文件。字段/REQ/文件引用检查属于结构验证，不能替代人工审查需求语义及表中算术。
