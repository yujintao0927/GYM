# TASK-BIZ001 集成说明

本库是 Java 单体模块库，无 Spring Boot 应用入口、HTTP 路由、前端、自动迁移装配或新中间件。仅有 M 层独立模块证据；不能将复合 REQ 或 I/U/L 标完成。

统一集成责任方须：
1. 将独立 POM 依赖纳入统一构建（本任务没有修改 backend/root）。运行环境补做 Java21 实机验证；本次为 Java22 javac release21。
2. 为 MerchantService 注入可信 IAM actor、当前 AccountDirectory、AuthorizationPort、平台权限来源及有批准来源/版本的 GrantPolicy。默认不接受 fixture 政策，OD-02 未批准分支返回 POLICY_UNAPPROVED。会员权益永远不能替代员工授权，员工授权也不能授个人付费资格。
3. IAM 到本模块的授权适配必须采用当前数据库授权，不能持旧角色/门店缓存放行。currentStaffDecision 是可信提供方读接口，只返回指定角色的当前显式门店范围，不判断平台权或会员资格。不存在公开 HTTP 旁路。
4. 用统一 DataSource/事务管理器装配；外部提供方适配须加入同一数据库事务及账号 epoch 栅栏，不能持锁调用网络。当前 fixture 不能证明真实 IAM/跨模块原子性；无法加入本地事务时先批准状态编排及失败补偿，不默认为分布式原子提交。
5. 当前仓储每次事务先锁 mch_mutex 单行，串行化本模块写及当前授权读；因此撤授提交后新判断不会使用旧授权。锁顺序与账号关闭/其他模块统一编排需专门评审，改变粒度前补并发基准与撤权测试。本任务未承诺吞吐/SLO。
6. 本模块 V3 只通过显式 classpath:db/modules/merchant-core 执行于 gym_dev_test_biz001。集成迁移按 V1–V8 串行装配，不能直接复用本测试库守卫去连接生产；正式数据库白名单适配和迁移批准由集成任务承担。禁止 clean/baseline 覆盖。当前数据库守卫在连接后校验 catalog、URL、表白名单、历史版本；连接前测试验证唯一 URL。
7. Outbox 与源状态/审计/回执同事务。集成添加受认证发送工作者、投递确认及失败重试；消费者用 eventId Inbox 去重。本模块没有消费外部事件，故不建无用途 Inbox，也不声称投递已完成。Outbox 只存最小变化事实，消费者须经授权查询当前状态；不得以事件替代实时授权。
8. 商家审核只处理人工审核资料的私有引用，不存证件正文、不下载附件；私有引用解析/附件逐次鉴权由真实提供方负责。人员身份只外部账号ID，无会员表、卡表、收费或支付写入。

服务期限的 end/graceEnd 必须由经批准的上游日历政策归一化后显式提供；本模块不推导自然日/时区/30天月。30天提醒及15天宽限主体要求保留，P01 日历细节未批准，提醒投递交运营模块，本模块不伪造站内或外部送达。未配置期限不得据此声称门店服务正常。服务状态变更不直接写权益，不恢复/补偿卡，也不更改其他门店或个人权益。

前端批准图与范围：不适用，本任务无前端页面或视觉实现。
