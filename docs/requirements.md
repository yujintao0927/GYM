# 智慧健身系统需求基线

更新日期：2026-11-11。用途：实际商业运营。状态：需求梳理中，尚未批准技术方案或进入实现。下列已确认事项依据需求讨论；待确认项不得当作已批准需求实现。

## 产品与终端

- 平台服务多个商家，一个商家支持多个门店。
- 微信小程序主要服务用户，Web 主要服务商家与平台，同时提供用户入口。
- 本地开发测试，后续部署上线；尚无服务器、微信小程序配置及支付资质。
- 商家按门店支付固定年费，金额待调研。个人会员价格、期限待确认；平台是否收办卡抽成待确认。
- 健身房会员办卡费用归商家；平台个人会员费用归平台。

## 身份与权限

- 同一个账号可以同时具有个人会员、多家健身房会员和员工身份。
- 用户可切换健身房；会员卡绑定具体门店，不支持跨店使用，也不支持跨商家使用（2026-11-11 用户修正确认）。
- 两类有效会员均可使用训练、饮食、图片热量识别等公共付费功能。
- 健身房会员具有所属健身房打卡、器械查询、内部排行榜等专属权益。
- 个人会员具有自由用户地域排行榜等权益；双身份用户拥有二者权益。
- 所有付费权益到期后仍可登录、查看历史健康记录及历史办卡记录，停止对应付费业务操作。
- 未付费普通用户开放体重、饮食、健身等手动记录功能；不据此开放 AI、图片识别或付费排行榜。
- 商家员工按商家及角色隔离数据与入口；店主、店长、前台、教练分别授权。
- 教练具有独立入口，平台具有管理员和客服入口。
- 商家仅可访问必要门店资料；用户私人健康记录经用户授权后对教练开放。

## 会员卡

- 支持日卡、月卡、季卡、年卡、次卡；商家选择启用卡种及定价。
- 不支持请假冻结、转卡、自动续费。
- 卡状态、有效期或次数，与入场、离场状态分开管理。
- 会员等级及其识别、计划生成额度和福利可配置；具体等级与配额待确认。
- 用户进入和离开健身房均记录；首期支持二维码签到签退及前台人工登记。
- 有效卡、到期卡和历史卡分别呈现；同账号其他商家及个人会员权益独立生效。

## 商家服务到期

- 到期前30天提醒商家续费。
- 到期后15天为宽限期，会员原有功能继续开放。
- 宽限期冻结商家部分功能，禁止新办卡、续卡、升级等新增收费办卡；保留服务费支付、退款处理与必要日常服务。完整操作权限表待确认。
- 超过宽限期仍未续费，暂停对应健身房提供的会员业务功能；保留登录、历史查询、退款和客服入口。
- 不自动转为个人会员，不由平台垫付会员退款。
- 商家续费后恢复商家功能及用户仍有效的权益；补回因平台停用损失的有效时长。补偿规则见本文末尾本轮决策。
- 用户独立购买的个人会员及其他商家权益不受影响。
- 商家7个自然日内完成退款审核并发起退款，到账时间另行展示；拒绝退款或超时未处理可转人工客服。
- 平台支持限制商家、保存投诉与处置记录、拉黑商家；具体处置与申诉权限待定义。
- 平台责任与商家责任需通过上线协议明确，不将“平台一律免责”当作系统可以保证的结论。

## 退款

- 由平台统一制定规则，商家不能自行更改。
- 期限类退款金额＝实付金额×剩余有效时长÷购买的总有效时长。
- 次数类退款金额＝实付金额×剩余次数÷购买总次数。
- 四舍五入到分，累计退款不超过实付金额，不追回折扣、不扣手续费；赠送时长或次数计入总权益。
- 健身房会员退款与私教订单退款分开申请、审核和记账，共用公式体系。
- 个人会员不提供普通业务退款；重复扣款、支付异常等处理另行定义，上线条款另行审核。
- 退款后关闭对应权益；日卡激活使用后的自助退款限制沿用已接受方案，服务异常转人工。
- 退款以申请时点计算，申请后暂停对应权益；私教按商品的期限或次数类型使用统一公式，细则见本轮决策。

## 健康与训练

- 体重与目标管理、身高、体脂与围度记录、趋势查询。
- 饮食手动记录、热量及营养素汇总。
- 食物图片识别后由用户确认或修改食物、分量，再估算热量并保存。
- 根据目标、训练经验、时间和器械制定可调整的计划，提供动作内容。
- AI 对话需要实现，提供商及配置在开发对应模块时由用户提供，不自行选择或写入凭据。
- 每日训练、饮食、体重记录；排行榜有效打卡另行计算。

## 打卡与排行榜

- 主要依据有效打卡天数，每自然日最多计一个有效打卡日，月榜及累计榜，同分并列。
- 健身房榜以出入场记录形成到店打卡，用户只能查看有资格访问的本健身房榜。
- 个人榜以平台售卖的健身手环数据形成训练打卡，首期模拟手环数据接入，不采用用户自行确认代替。
- 双身份分别满足条件后可进入两类榜单。
- 默认不参与，用户主动开启；默认昵称为用户名，支持异常成绩处理与申诉。
- 个人榜可选择全国、省、市、区；经授权自动定位，仅保留地区信息，不公开精确位置。
- 拒绝定位仍可使用其他功能及全国榜；地区归属每月最多变更一次。
- 有效到店条件、手环训练阈值、防重复、异常数据及地区人数不足规则待定义。

## 首期商家与平台功能

- 商家入驻人工审核、门店资料、员工及角色权限、会员身份与卡状态管理。
- 收入分别统计实收、退款、净收入；经营看板包含新增、续费、到店等指标。
- 区分会员总数、今日到店人数和当前在场人数；离场数据不可靠时标注估算。
- 会员到期续费提醒、沉默会员识别与召回；具体触达规则待定义。
- 器械档案、可用、故障、维修、停用状态；员工更新，会员报修，保留维修记录。
- 首期包含团课预约：排课、人数限制、预约、取消、签到。
- 首期包含独立收费私教服务，支持期限订阅和次数课包，由商家选择启用；包含教练时段、预约、扣次、取消及退款。
- 团课和私教收费及预约取消扣费由商家制定，付款前明示；会员卡及私教订单退款仍按平台统一公式。
- 平台管理商家、套餐、订单、退款、客服工单、投诉处置及权限。
- 客服工单支持文字与图片；先提供站内消息，微信订阅消息待账号和授权条件就绪后接入。

## 支付与集成

- 开发期模拟支付，模拟与真实交易必须明确区分，不生成真实收款声明。
- 需要设计微信、支付宝、银行卡支付的统一接口、状态、回调、退款、对账及异常处理能力。
- 在资质与配置可用后接入真实渠道并验证；预留接口或模拟成功不等于真实支付已经完成。
- 银行卡具体指快捷支付、网关支付还是转账待确认；商家结算方式和线下收款登记待确认。
- 手环首期模拟数据，后续设备协议和真实数据接入独立验收。
- 本地 MySQL 连接按用户全局规则使用，数据库名待确认；文档及跟踪文件不记录密码。

## 已废弃方案

- 商家停费后将健身房会员自动转换为个人会员：用户已明确否决。
- 首期以用户自行确认作为个人排行榜打卡：已改为模拟手环数据。
- 首期包含福利与智能报警：已调整，不能按早期讨论误实现。
- 请假冻结、转卡、自动续费：不支持。

## 2026-11-11 本轮确认与授权决策

来源：本轮用户两次明确答复及“你认为怎么合适，怎么更能吸引用户并盈利就怎么做决定”的授权。下列区分直接确认和协调者受托决定，不代表已经实现。

- 用户直接确认：单店卡、不支持跨店卡、不支持转卡；同账号可持多个门店的独立卡。此前“同商家跨店”要求由本轮明确修正取代。
- 用户直接确认：退款按申请时点计算；免费用户支持体重、饮食、健身等记录；不设置年龄准入限制；团课/私教收费及取消扣费由商家制定。
- 用户直接确认架构方向：单体分模块、统一数据库，支付/AI/设备通过适配接口；尚未选择编程语言、框架或数据库名称。
- 协调者受托决定：退款申请后暂停本次申请对应权益，按申请时点的金额、剩余权益和规则快照计算；驳回或用户撤回时恢复并补回审核暂停导致的有效时长损失；成功退款关闭对应权益，不影响独立的其他卡或个人会员。期限卡全退剩余、次卡退剩余次数；单笔不开放任意部分退款，同一订单只允许一个处理中申请，避免反复申请获利。
- 协调者受托决定：商家停用补偿以宽限结束后的实际停用区间，与每份期限卡原本可用区间的交集计算，扣除已补偿区间；包括停用期间到期的卡。续费恢复时将实际损失时长接回至恢复时点（仍有效卡在原到期日后追加），不得重复补偿；已退款部分不补；次卡不凭空赠次数，有期限的次卡只补损失有效时长。补偿及退款期间重叠时长不得重复增加，退款快照须纳入既有补偿。
- 协调者受托决定：期限及次数私教商品均支持，商家选择启用；退款依商品快照选择平台统一期限或次数公式。商家预约取消扣费仅适用已明示且用户接受的预约政策，未明示不扣费；不得修改会员/私教订单统一退款公式、叠加退款手续费或重复扣款。扣次/扣费先记录，剩余权益退款按申请快照计算。
- 协调者受托决定：健康资料按教练、资料类别和期限单独授权，默认不开放；撤回后立即阻止新访问。注销入口需说明权益/未结交易影响并再次确认；注销后立即撤销会话和授权、停止非必要处理，对依法或争议处理所必需的记录隔离保留，其余删除或去标识化。具体期限和未成年人必要授权经上线规则核查确定，未核查不得商用上线；本轮不采集人脸数据。
